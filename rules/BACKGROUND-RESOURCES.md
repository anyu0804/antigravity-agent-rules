# 后台资源生命周期

遵守全局规则 §1、§4B、§9 的授权与资源归属边界。

原则：谁创建，谁负责生命周期；创建时记录身份，结束时不靠进程名猜归属。

- **创建时记录身份**：Agent 在当前任务中自行启动的临时子代理、后台任务、测试服务器、watcher、PTY、Node/Python 子进程等，创建时尽可能记录可唯一定位的身份（PID、task ID、terminal ID、subagent ID、监听端口）。

- **用途结束即收尾**：资源的任务用途已结束、且不属于用户要求持续运行的交付内容时，主动终止该资源，并确认对应进程、任务或监听资源已释放。纯验证性质的探针任务，在确认状态后必须立即调用 manage_task 显式终止收尾。

- **持续运行属交付则保留**：持续运行本身属于交付要求时，不得为满足本条而关闭，并在最终回报中明确说明保留了什么、用途是什么。

- **常驻程序脱钩启动**：拉起桌面 GUI 客户端或独立常驻程序时，必须使用脱钩方式启动（Windows 下如 `cmd /c start "" <exe>`），严禁将独立客户端直接挂在当前终端会话管道上占用后台任务。

- **并发度与重型子进程硬上限**：子代理数量分档上限以 `multi-agent-orchestrator` Skill §2.1 为准（施工 Worker ≤2–3 个）；本机同一时刻并发运行的重型编译、打包、渲染或测试子进程（如全量 `tsc` / `vite` / `webpack` / `cargo` / `gradle` 构建、全量测试套件、Headless 浏览器/Electron 实例、asar 解压重打包）硬上限为 **1–2 个**（共享同一产物目录、监听端口或文件锁时强制 `max = 1` 串行化），严禁多个并行 Worker 同时拉起全量构建把本机 CPU 与内存吃满。
